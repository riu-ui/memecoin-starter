Why cloud AI is blocked on the live site — and the fix (read this first)
  1. Diagnosis (confirmed on the live site, signed in, phone browser): since Nov 2, 2026, Firebase enforces App Check for AI Logic — this project shows “Registered (Enforced)” in the console. Every cloud request must carry a valid App Check token. This page previously sent none: no reCAPTCHA Enterprise site key was set, so App Check was never initialized, and the debug-token flag was switched on for the live domain, which does nothing for real visitors. Firebase rejects the request before it reaches Gemini, and the SDK surfaces that rejection as a generic network / fetch error — that is the misleading “Network problem” message in the screenshot, not a connection problem.
  2. Production fix (about 5 minutes, one time): open Firebase Console → App Check → Apps, open the Planning With AI web app — if the AI Logic setup auto-registered a reCAPTCHA Enterprise provider, its site key is shown there. If there is no key yet, create a score-based website key for riu-ui.github.io in Google Cloud → Security → reCAPTCHA, register it for this app in App Check, then paste the site key (it is public by design and safe to ship in a page) as AI_APPCHECK_SITE_KEY at the top of this page’s AI script and republish the live site. This page now initializes App Check and waits for it before the first AI request, and requests limited-use App Check tokens as AI Logic expects.
  3. Temporary judging workaround (only if the console offers it): Firebase Console → App Check → APIs → Firebase AI Logic API → delay the enforcement date (latest Jan 21, 2027). While enforcement is delayed, cloud answers work without a token; wire the site key before the delay expires.
  4. Why the old debug-token advice could never fix the live site: a debug token is random per browser, must be copied out of a desktop browser console and registered by hand — a phone browser has no console to copy it from, and no visitor can register theirs. Debug mode is now enabled on localhost only, never on the live domain.
  5. Also fixed in this page: the cloud model is pinned to gemini-2.5-flash (the floating gemini-flash-latest alias is gone), and on phones — where Gemini Nano does not exist — Hybrid mode now goes straight to the cloud model instead of attempting an on-device session first.
  6. On-device (Chrome desktop): use Chrome 139+ and enable chrome://flags/#prompt-api-for-gemini-nano-multimodal-input, then restart Chrome. The first on-device request may download Gemini Nano — the Analyze button shows download progress. On-device mode never needs App Check.

🎓 Read Data Like on Memecoin Sites

Terms used by CoinGecko, DexScreener, and Pump.fun — so the numbers on this page make sense.

Market Cap & FDV

Market cap = price × circulating supply. FDV = price × max supply. An FDV far above market cap means many locked tokens could still flood the market.

Liquidity

Money available in the pool for buying and selling. Below $10k is very thin: prices are easy to manipulate and positions are hard to sell. The radar on this page gives a Safety Score based on liquidity, age, FDV, and volume.

Turnover (Volume / MCap)

Above 10% = very active. High can mean healthy hype, or wash trading — always check that volume is consistent with price movement.

Anti-Rug Checklist

A brand-new pool + thin liquidity + gains of thousands of percent within minutes = the classic rug pull pattern. Don't jump in just because of FOMO; most radar tokens under 1 hour old on this page don't last long.
